# Standard: Multilingual strings

## Applies to
Every sentence a person sees. This covers the page (HTML and JS for the yard and the overlay), error and status messages the backend returns to the page, window titles and the tray menu, and file dialog titles. Supported languages are Korean (`ko`), English (`en`), Japanese (`ja`), and Simplified Chinese (`zh-hans`).

Not covered:
- Sentences the app's CLI mode writes for the terminal and coding agents (usage, errors, MCP tool descriptions). These are fixed in English.
- The template sentences of prompts sent to the AI (`chat/prompt.rs`). These are written in English, and the prompt sets the reply language.
- Words sent by an agent or a person (`say`, AI replies). These are shown as they are, without translation.
- Test code, comments, and developer docs (`docs/`), which are written in English. Dated design records and decision records stay as they are.

## Rules
- Page strings live in `src/core/strings/<language>.js` and backend strings in `src-tauri/src/i18n/<language>.rs`. The Korean file is the reference; other languages have the same keys in the same order. No other module or markup contains Korean sentences. The steps for adding a language are in [Add a language](../how-to/add-a-language.md).
- Every language has the same keys, and the sentences for one key have the same placeholders (`{name}`).
- Every key the code calls (`t('…')`, `list('…')`, `data-i18n`, `data-title`, `i18n::t("…")`) exists in the table. A missing key shows the key name itself on screen.
- Key names use lowercase and dots, with the area first (`invite.open_folder`, `error.pet_missing`). When the same sentence repeats, reuse the key.
- Korean uses the polite 해요 style, English uses short sentences (only the first letter capitalized), and Japanese page strings use the です・ます style. Simplified Chinese uses plain, friendly 你 (never 您) with full-width punctuation. Pet speech bubbles use casual speech in every language.
- In Korean, the particle after a name is attached to the placeholder (`{name:을/를}`, `{name:이/가}`, `{name:은/는}`, `{name:과/와}`). The particle that matches whether the name ends in a final consonant is filled in automatically.
- Coding agent status is sent as codes (`@thinking`, `@tool Bash`, `@done`). The app receives them and turns them into `agent.*` keys. When you add a new status, add the code and the key together.
- Do not change the terms below.

| Term | Meaning |
|---|---|
| Pet (`펫`) | A character file (pet.json and the sprite sheet) |
| Friend (`친구`) | Someone invited into the yard |
| Import (`가져오기`) | Bringing in pet files |
| Invite (`초대하기`) | Adding a friend to the yard from a pet |
| AI connection (`AI 연결`) | The AI a friend uses to chat (Claude Code, Codex, Ollama, OpenAI-compatible) |
| Agent integration (`에이전트 연동`) | Hook and MCP settings for coding agents |
| Yard, mini mode, desktop (`놀이터`, `작게 보기`, `바탕화면`) | The main window, the small window mode, the desktop overlay |

This is how the page uses it.

```js
import { t } from '../core/i18n.js';
await confirmAction({ title: t('friend.send_away_confirm', { name: pet.name }) }); // 프리렌을 놀이터에서 내보낼까요? ("Send Frieren away from the yard?")
```

```html
<button id="update-button" data-i18n="settings.update_check"></button>
<input data-i18n-placeholder="chat.placeholder">
```

This is how the backend uses it.

```rust
return Err(i18n::tr("error.pets_limit", &[("limit", &LIMIT.to_string())]));
```

## Recommendations
Follow these when you can. When you cannot, say why in the PR.
- Spell out development terms (config, provider, sprite) in sentences people see.
- Error messages say what failed and what the person can do (“Check your internet connection”).

## Exceptions
| When | How |
|---|---|
| Code that handles Korean itself, such as particle handling (`src/core/words.js`) | Allowed. It is already in the guard test's exception list |
| Proper nouns and language names (the 한국어 / English / 日本語 / 简体中文 choices) | Allowed. They are not translated |
| You cannot fill every language at once | Do not leave them empty in English; split the PR. Tests block empty strings |

## Rationale
When strings are scattered through the code, they cannot be translated and the terms drift. Gathering them into two tables lets tests catch missing and mismatched entries. Agent hooks run in a different process from the app and do not know the app's language, so they send codes.
Based on: decision “[Strings live in two per-language tables, one for the page and one for the backend, and agent status is sent as codes](../decisions/2026-09-30-strings-in-two-tables.md)”

## Automated checks
- `tests/i18n.test.mjs` — matching keys and placeholders across every language, Korean in page code and markup, comments included (only `strings/ko.js`, `words.js` and `i18n.js` may show it), and that the keys the page calls exist.
- Rust `i18n::tests` — matching keys and placeholders across every language, Korean in every `src/` module, comments included (test modules may use Korean input data), that the keys the backend calls exist, and agent code conversion.
