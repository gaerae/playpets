# Add a place for friends

Start with [the places design](../design/2026-10-11-places.md), which describes the registry, capabilities, floor geometry and weather behind window panes. A place shares the app's friends and activities; its artwork and capabilities describe where they are standing.

1. Add one entry to `src/content/worlds.json`. Choose a stable `id`; changing it later sends saved choices back to Woodland. Add its `label` and `about` activity-note keys to all four page string tables.
2. Set `geometry.fieldTop` to the back edge of the walkable floor, as a fraction of the image height. Keep enough open foreground for the full cast and the tools. A fishing place also needs `geometry.lake` with `from`, `to`, `center` and `radius`; those fractions describe the same raster water that people click.
3. Set each capability deliberately: `sky`, `weather`, `wildlife`, `fishing`, `seasonalEffects` and `ambient`. An indoor place normally disables outdoor activities. To show weather through its windows, enable `weather` and define `windowPanes` as normalized `x`, `y`, `width` and `height` rectangles over the glass. Rain, snow and overcast shading share the background crop and stay inside those panes. Do not enable fishing to make an activity button work when the image has no usable water.
4. Put generated or illustrated images in `src/art/environments/` and name them in `art.morning`, `art.day`, `art.evening` and `art.night` when they have authored lighting, and set `"authoredLighting": true` so `environmentLook` does not tint the painted light again; without it each time of day gets the outdoor filter and tint. Preserve prior source assets. Use `fit: "cover-floor"` (or `"cover-bottom"`, which aligns the image's bottom edge instead of its floor line) to keep the image's proportions and anchor its floor to `geometry.fieldTop` as the window changes shape. `environmentFrame` shares this transform with pond geometry, window weather and seasonal lights. Review visible water and automatic fishing endpoints after cropping before enabling fishing.
5. Add lighting to `environmentLook` when the new material or lamp light needs it. Review the actual image in every time of day: a warm night room needs readable walls and floor, with a genuinely nighttime view through its window.
6. Give the new place's atmosphere its own `chatter` string-table key containing casual idle lines in all four languages. Indoor places need their own lines so friends do not talk about outdoor stars or studio lamps in another room. A café or city sound palette needs a distinct implementation and tests; enabling `ambient` currently selects the woodland mix.
7. Add capability, geometry, asset and translation checks to `tests/worlds.test.mjs`, changing tests before changing their rules. Add real visual fixtures through `scripts/visual-audit.mjs`, including day, night, full size, 500×350, 320×240 and a wide mini strip. Verify that changing worlds ends fishing and games and retains friends and collections.

The existing modules consume registry data without extra entry-point wiring. `loadContent()` loads the registry; `setupSky()` builds the Place select from its entries, saves the chosen id and applies the new scene. Unknown saved ids return to Woodland.

Run the repository's normal checks before integrating a place: Node and Rust tests, lint, the site build for documentation changes and real-app E2E for the selector flow. Isolated fixtures make the result reviewable, but they do not replace native interaction checks.
